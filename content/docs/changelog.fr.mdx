# Journal des modifications

## v7.0.0 — 2026-11-27

La 7.0.0 est une version majeure (Cloud et Self-host) : les cinq outils de la base de connaissances et la couche JWT Clerk refusent ce que la 6.0.0 acceptait.

### Modifié (incompatible)

- **Les outils de la base de connaissances refusent un bearer sans organisation vérifiée** — `store_document_chunked`, `soft_delete_document`, `claim_upload` et `generate_upload_url` (avec et sans `sha256`) refusent un bearer qui n'est ni le master ni une session Clerk et n'a aucune organisation vérifiée. Le refus est `RBAC_DENIED` avec la raison `verified-org-unresolved`, et aucun appel au backend n'est fait ([#1804](https://github.com/vantageos-agency/vantage-peers/issues/1804)). Les appelants master et session Clerk sont inchangés. Le Cloud n'est pas concerné : la production compte 0 bearer sans slug d'organisation.
- **Self-host : `CLERK_DOMAIN` est désormais requis aussi par la couche JWT Clerk, `whoami` et le jeton d'administration d'organisation**, et plus seulement par l'émission du jeton de compte de service. Une valeur absente, vide ou composée d'espaces est refusée au lieu de retomber sur une instance Clerk de développement ([#1802](https://github.com/vantageos-agency/vantage-peers/issues/1802)). Le Cloud n'est pas concerné : `CLERK_DOMAIN` est défini sur Railway. Voir [Variables d'environnement](/docs/self-host/env-vars).

### Modifié

- **ID d'agent vérifié transmis** — les outils transmettent l'ID d'agent vérifié de l'appelant aux portes du backend qui le prennent, et refusent par un `RBAC_DENIED` typé avant la porte un appelant qui n'en a pas là où la porte n'en admet aucun (`accept_mandate`, `update_mandate`, `settle_mandate` ; `debate_get_room` et `improvisation_digest` pour un appelant qui n'est pas une session Clerk). Un producteur unique construit tous les refus d'identité ([#1803](https://github.com/vantageos-agency/vantage-peers/issues/1803)).
- **`get_memory` transmet l'organisation vérifiée de l'appelant** à la porte du backend ([#1804](https://github.com/vantageos-agency/vantage-peers/issues/1804)).

### Corrigé

- **Pagination de `list_bus`** — `list_bus` transmet le `nextCursor` `{time,id}` qu'il émet, donc sa page 2 est atteignable. `list_bus` et `list_repo_mappings` refusent un curseur de forme inconnue au lieu de repartir silencieusement à la page 1 ([#1807](https://github.com/vantageos-agency/vantage-peers/issues/1807)).

### Notes de migration

- Appeler les outils de la base de connaissances avec un bearer qui porte une organisation vérifiée.
- Self-host : définir CLERK_DOMAIN avant la mise à niveau, sinon tout JWT Clerk est refusé.

## v6.0.0 — 2026-11-27

La 6.0.0 est une version majeure (Cloud et Self-host).

### Modifié (incompatible)

- **`create_recurring_task` exige `project`** — un planning sans `project`, ou avec un `project` vide ou composé d'espaces, est refusé. Chaque tâche générée par le planning porte ce projet, et la facturation regroupe les tâches terminées par projet ([#1800](https://github.com/vantageos-agency/vantage-peers/issues/1800)). Voir [Tâches récurrentes](/docs/capabilities/recurring-tasks).
- **Self-host : `CLERK_DOMAIN` est requis pour l'émission du jeton de compte de service** — il n'a aucune valeur par défaut. Une valeur absente, vide ou composée d'espaces est refusée avant tout appel à Clerk, avec une erreur qui nomme `CLERK_DOMAIN` ([#1795](https://github.com/vantageos-agency/vantage-peers/issues/1795)). La vérification des JWT Clerk applique encore une valeur par défaut pour cette variable en 6.0.0. Voir [Variables d'environnement](/docs/self-host/env-vars).
- **Les lectures `ui://` transmettent l'organisation vérifiée de l'appelant** — un bearer qui ne porte aucune organisation est refusé ([#1801](https://github.com/vantageos-agency/vantage-peers/issues/1801)).

### Corrigé

- **Pagination de `list_repo_mappings`** — les pages au-delà de la première se lisent en repassant le `nextCursor` retourné dans `cursor`. Une page qui contient une ligne hors périmètre est servie : sur cette ligne `orchestrator` est absent et `outOfScope.reason` en donne la raison ([#1805](https://github.com/vantageos-agency/vantage-peers/issues/1805)). Voir [list_repo_mappings](/docs/cloud/mcp-tools/list-repo-mappings) (page en anglais).
- **Journal de démarrage** — le serveur journalise le port d'écoute, jamais le nom d'hôte ([#1797](https://github.com/vantageos-agency/vantage-peers/issues/1797)).

### Notes de migration

- Les appelants de `create_recurring_task` doivent passer `project`.
- Self-host : définir `CLERK_DOMAIN` (l'origine de l'API Frontend de l'instance Clerk qui a émis `CLERK_SECRET_KEY`) avant la mise à niveau.

## Non publié

### Retiré

- **Outils du registre de composants retirés** — `register_component`, `get_component`, `list_components`, `update_component`, `delete_component` et `search_components` ne sont plus servis par le serveur MCP VantagePeers ; la table `components` a été supprimée. VantageRegistry est la source de vérité pour la gestion des composants (agents, skills, hooks, plugins). Les chemins d'authentification bearer legacy DCR (`oauthClients`/`oauthTokens`) et `mcpTenants` ont également été retirés et refusent désormais.

## v2.4.1 — 2026-05-30

### Corrigé

- **Régression 401 sur le chemin d'auth DCR** ([#556](https://github.com/vantageos-agency/vantage-peers/issues/556) / [#557](https://github.com/vantageos-agency/vantage-peers/pull/557)) — `oauthDcr:validateAccessToken` était déclaré `internalQuery` et inaccessible via le client HTTP, le Path 3 DCR retournait 401 même avec un token valide. Maintenant exposé en `query` publique. Les connecteurs custom Claude.ai via DCR fonctionnent de bout en bout.
- **Format du header `WWW-Authenticate`** ([#557](https://github.com/vantageos-agency/vantage-peers/pull/557)) — émet `Bearer resource_metadata="..."` selon la spec MCP §Protected Resource Metadata Discovery. L'ancienne forme `Bearer resource="..."` cassait le bootstrap PRM de Claude.ai sur 401.

### Ajouté

- **Annotations d'outils ChatGPT Apps SDK** ([#555](https://github.com/vantageos-agency/vantage-peers/pull/555)) — les 84 outils MCP embarquent désormais `readOnlyHint`, `openWorldHint` et `destructiveHint`. 34 read-only + 41 write + 9 destructive. Les connecteurs custom ChatGPT n'affichent les prompts de confirmation que sur les opérations d'écriture/destructives.
- **Isolation de scope DCR** ([#554](https://github.com/vantageos-agency/vantage-peers/pull/554)) — nouveau profil `public-readonly` + tests cross-tenant. Le flux DCR auto-discovery résout vers `scopeProfile=client-generic` (jamais `master`), même si un legacy token row porte `scope="mcp:full"`.
- **Documentation VantagePeers Cloud** ([site #120](https://github.com/vantageos-agency/vantage-peers-site/pull/120)) — section `/docs/cloud/` dédiée à la version hébergée multi-tenant. Multi-client MCP : Claude.ai, ChatGPT, Claude Code, Codex, tout IDE supportant MCP.

## v2.3.1 — 2026-05-26

### Ajouté

- `list_tasks`, `list_missions`, `list_tasks_by_mission` et `list_briefing_notes` acceptent un paramètre `fields` (`"lite"` ou `"full"`, défaut `"full"`). Lite renvoie une projection compacte.
- Le filtre `status` sur `list_tasks`, `list_missions` et `list_tasks_by_mission` accepte désormais des tableaux et des alias nommés :
  - Tâches : `"open"` → todo+in_progress+review+blocked, `"active"` → todo+in_progress, `"all"` → aucun filtre
  - Missions : `"open"` → brainstorm+plan+execute+validate (exclut complete), `"active"` → plan+execute, `"all"` → aucun filtre

### Rétrocompatibilité

- Le `status` chaîne unique reste inchangé.
- Omettre `fields` revient à `"full"` — les appelants existants ne sont pas affectés.

### Dépréciation

- **`vantage-peers-mcp@2.3.0` est déprécié.** v2.3.0 a livré deux blockers détectés en delta-review : `status="all"` était annoncé mais rejeté par le backend, et `setPendingAliasReleases` était exposé en mutation publique. Passez à `>=2.3.1`.
