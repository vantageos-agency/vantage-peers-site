VantagePeers Cloud est le produit hébergé multi-tenant. Un seul backend, partagé par tous les clients MCP : **Claude**, **ChatGPT**, **Grok**, Codex, Claude Code et tout IDE parlant MCP. L'URL du serveur est la même partout :

```
https://mcp.vantagepeers.com/mcp
```

## Le modèle : un agent par assistant et par compte

Chaque assistant connecté agit comme **son propre agent**, avec un nom que tu choisis. Le même email peut se connecter sur tous les assistants. Un second compte sur le même assistant (par exemple un second compte ChatGPT) est une **connexion séparée avec son propre agent**. Mesuré le 2026-10-31 : une personne a connecté quatre assistants, et chaque consentement a posé l'agent choisi sur le jeton (Claude, deux comptes ChatGPT, Grok).

## La page de consentement (tous les assistants)

Quel que soit l'assistant, le parcours se termine sur la même page de consentement :

1. Choisis l'**organisation**.
2. Choisis l'**agent** que cet assistant incarne. **Connect as myself** (se connecter en tant que moi-même) est le choix par défaut.
   - Un membre ne voit que les agents déjà rattachés à lui.
   - Un admin d'organisation voit aussi les agents non rattachés et peut en créer un.
3. Valide.

## Claude (utilise le plugin, pas un connecteur nu)

1. Ouvre **Personnalisation > Plugins > Ajouter une marketplace**, saisis `https://github.com/vantageos-agency/vantage-peers-claude`, puis installe **Vantage peers**.
2. Ouvre **Personnalisation > Plugins > Vantage peers**, onglet **Connecteurs**, puis clique **Se connecter**. Crée ton compte ou connecte-toi, puis termine la [page de consentement](#la-page-de-consentement-tous-les-assistants).
3. Dans une conversation, clique **+ > Connecteurs** et vérifie que **vantage-peers** est activé.
4. Pour te reconnecter : **Déconnecter**, puis **Se connecter**.

<Callout type="warning">
Installer le plugin ne le connecte **pas**. Si tu sautes l'étape 2, Claude répond que le connecteur n'est pas actif dans cette conversation.
</Callout>

## ChatGPT

1. Ouvre **Plugins**, clique **+**, choisis **Add custom MCP server**.
2. Nom : `VantagePeers`. URL : `https://mcp.vantagepeers.com/mcp`. Authentification : **OAuth**.
3. Coche l'avertissement, puis clique **Create as plugin**.
4. Connecte-toi et termine la [page de consentement](#la-page-de-consentement-tous-les-assistants).

### ChatGPT peut-il écrire ?

L'article d'aide OpenAI 12584461 indique que les connecteurs MCP personnalisés ont un accès complet (lecture et écriture) sur les forfaits Business, Enterprise et Edu, et en lecture seule sur Pro. Nous le citons comme déclaration d'OpenAI. Nous avons aussi observé, le 2026-10-31, un forfait ChatGPT **Free** écrire une mémoire dans VantagePeers Cloud (53 secondes après l'émission de son jeton). Les règles de forfait sont celles d'OpenAI et peuvent changer : si une écriture est refusée, vérifie d'abord ton forfait.

## Grok

1. Ouvre **Connecteurs > Nouveau connecteur > Connecteur personnalisé**.
2. Nom : `VantagePeers`. URL : `https://mcp.vantagepeers.com/mcp`.
3. Ajoute-le, puis connecte-toi, et termine la [page de consentement](#la-page-de-consentement-tous-les-assistants).

## Tester

Colle ceci dans l'assistant juste après la connexion :

```
Appelle whoami et dis-moi le nom de l'agent et l'organisation que tu incarnes.
Désormais, enregistre automatiquement les décisions dans VantagePeers. Avant de
répondre à ce qui a été décidé ou à ce qu'il reste à faire, cherche d'abord
dans VantagePeers.
```

La réponse doit nommer l'agent choisi sur la page de consentement et ton organisation. Demande ensuite : *« Qu'avons-nous décidé jusqu'ici ? »*

## Dépannage

- **Le lien de l'email d'invitation ouvre `https://mcp.vantagepeers.com/mcp` et affiche `{"error":"Missing Authorization header..."}`** — cette URL est le serveur, pas une page de connexion. Connecte-toi plutôt via le connecteur de l'assistant. Un correctif du lien est en attente.
- **Claude : plugin installé mais « le connecteur n'est pas actif dans cette conversation »** — le plugin n'est pas encore connecté. Fais l'étape 2 de la section Claude.
- **Un outil attendu manque ou se comporte comme une ancienne version** — un client connecté avant une mise à jour du serveur garde les définitions d'outils en cache. Déconnecte puis reconnecte une fois.
- **Les écritures sont refusées avec « agents autorisés par la connexion : ... »** — l'agent manque dans le roster de ton organisation. Rien à faire côté client : contacte l'opérateur VantagePeers.
- **« aucun agent ne t'est attribué »** — aucun agent n'a été choisi ou rattaché. Reconnecte-toi et choisis l'agent sur la [page de consentement](#la-page-de-consentement-tous-les-assistants).
- **`401 Unauthorized`** — jeton expiré ou invalide. Les clients le rafraîchissent seuls ; sinon déconnecte puis reconnecte.
- **`403 Forbidden`** — ton scope ne couvre pas cette ressource (ton organisation uniquement).

## Claude Code (CLI, développeurs)

**Public cible :** développeurs avec Claude Code installé localement.

La façon recommandée de connecter Claude Code est d'utiliser le marketplace de plugins Claude Code. Une commande te donne la connexion au backend MCP **plus** 37+ skills, 7 hooks de qualité et 9 commandes slash — sans édition manuelle de `.mcp.json`.

Le plugin (`@elpiarthera/vantage-peers-plugin`) embarque un manifeste `.claude-plugin/plugin.json` à la racine, ainsi que les répertoires `skills/`, `agents/`, `commands/` et `hooks/`. Il câble le serveur MCP VantagePeers automatiquement et enregistre la suite complète d'outils de mémoire, messagerie et tâches dans ton workspace Claude Code.

### Installer

```bash
claude plugin install @elpiarthera/vantage-peers-plugin
```

Pour la documentation et la découverte du marketplace, voir la référence [Claude Code plugin marketplaces](https://code.claude.com/docs/fr/plugin-marketplaces).

### Configurer les identifiants Cloud

Après l'installation, renseigne tes identifiants dans `.mcp.json` à la racine du workspace :

```json
{
  "mcpServers": {
    "vantage-peers": {
      "type": "http",
      "url": "https://vantage-peers-production.up.railway.app/mcp",
      "oauth": {
        "client_id": "YOUR_CLIENT_ID",
        "client_secret": "YOUR_CLIENT_SECRET"
      }
    }
  }
}
```

Redémarre Claude Code (`exit` puis relance depuis ton workspace). Au premier appel, le client exécute le flux PKCE contre `/authorize` et `/token`, met en cache l'access token et le rafraîchit automatiquement.

### Vérifier

```
/vantage-peers-init
```

La commande exécute 3 vérifications (enregistrement MCP, connectivité `/health`, auth Bearer via `recall`). Les 3 doivent afficher `PASS`. Puis enchaîne avec :

```
/daily-start
/check-messages
/check-tasks
```

### Fallback manuel (sans plugin)

Si ton build Claude Code ne supporte pas les plugins, ou si tu travailles dans un environnement contraint, configure le serveur MCP manuellement — ajoute `vantage-peers` à ton `.mcp.json` projet (ou global `~/.claude.json`) :

```json
{
  "mcpServers": {
    "vantage-peers": {
      "type": "http",
      "url": "https://vantage-peers-production.up.railway.app/mcp",
      "oauth": {
        "client_id": "YOUR_CLIENT_ID",
        "client_secret": "YOUR_CLIENT_SECRET"
      }
    }
  }
}
```

Si ton build Claude Code ne supporte pas encore le champ `oauth`, pré-émets un access token via PKCE (voir [Émettre un access token manuellement](#émettre-un-access-token-manuellement) ci-dessous) et utilise-le ainsi :

```json
{
  "mcpServers": {
    "vantage-peers": {
      "type": "http",
      "url": "https://vantage-peers-production.up.railway.app/mcp",
      "headers": {
        "Authorization": "Bearer YOUR_ACCESS_TOKEN"
      }
    }
  }
}
```

Les access tokens sont de courte durée. Refresh via le endpoint `/token` avec `grant_type=refresh_token` quand ils expirent.

## Codex (CLI OpenAI)

Codex supporte MCP via son `~/.codex/config.toml` (ou équivalent au niveau projet) :

```toml
[[mcp_servers]]
name = "vantage-peers"
url = "https://vantage-peers-production.up.railway.app/mcp"
type = "http"

[mcp_servers.oauth]
client_id = "YOUR_CLIENT_ID"
client_secret = "YOUR_CLIENT_SECRET"
```

Si ton build Codex ne supporte pas encore le bloc `oauth`, fallback sur un access token pré-émis dans les headers (même pattern que Claude Code manuel ci-dessus).

1. Enregistre la config.
2. Redémarre `codex` pour qu'il prenne le nouveau serveur.
3. Lister les outils : `codex mcp list` doit inclure `vantage-peers`.
4. Test : demande à Codex *« appelle recall avec query=hello »*.

## Google Antigravity

Antigravity lit les serveurs MCP dans un seul fichier global, `~/.gemini/config/mcp_config.json`. Ce fichier unique s'applique à tous les workspaces de la machine. La [page MCP](https://antigravity.google/docs/mcp) de Google indique (en anglais) que le fichier de configuration "is located globally at `~/.gemini/config/mcp_config.json` (or locally in your workspace under `.agents/mcp_config.json`)". Google ne documente ni la fusion des deux fichiers ni lequel l'emporte, et VantagePeers n'a pas vérifié que l'IDE charge le fichier de workspace : place l'entrée dans le fichier global.

Pour les skills et l'installeur guidé, voir [Plugin](./plugin). L'entrée ressemble à ceci, avec des placeholders à remplacer par les valeurs de ton siège :

```json
{
  "mcpServers": {
    "vantage-peers": {
      "serverUrl": "https://<your-vantagepeers-cloud-endpoint>/mcp",
      "headers": {
        "Authorization": "Bearer <seat token>",
        "x-vantage-agent-credential": "<agent credential>",
        "Content-Type": "application/json"
      }
    }
  }
}
```

Les serveurs distants doivent utiliser le champ `serverUrl`. Les champs `url` et `httpUrl` ne sont pas pris en charge par Antigravity.

### Plusieurs agents sur une même machine

Crée une entrée par agent, nommée `vantage-peers-<agent>`, avec son propre token de siège et sa propre credential d'agent. Les instructions de chaque agent doivent nommer l'entrée qu'il utilise. Si deux agents partagent le même nom d'entrée, l'un agit silencieusement avec l'identité de l'autre.

```json
{
  "mcpServers": {
    "vantage-peers-<agent-a>": { "serverUrl": "https://<your-vantagepeers-cloud-endpoint>/mcp", "headers": { "...": "clés de l'agent A" } },
    "vantage-peers-<agent-b>": { "serverUrl": "https://<your-vantagepeers-cloud-endpoint>/mcp", "headers": { "...": "clés de l'agent B" } }
  }
}
```

### Vérifier que ça marche

Redémarre Antigravity, puis demande à l'agent : *"Check your messages, then send a message saying hello."* Le panneau MCP doit afficher l'entrée activée, avec ses outils listés.

<Callout type="warning">
Ne colle jamais de clés dans un chat, un commit ou un écran partagé. Garde-les dans des fichiers que toi seul peux lire.
</Callout>

### Autres fichiers de réglages : `settings.json`

Un `~/.gemini/settings.json` (utilisateur) et un `.gemini/settings.json` de projet existent, mais ils relèvent de Gemini CLI, pas d'Antigravity.

- La [référence de configuration de Gemini CLI](https://geminicli.com/docs/reference/configuration/) de Google indique que le fichier utilisateur `~/.gemini/settings.json` "Applies to all Gemini CLI sessions for the current user" et que le fichier de projet `.gemini/settings.json` "Applies only when running Gemini CLI from that specific project" et "Project settings override user settings and system defaults". Gemini CLI lit `mcpServers` dans ces fichiers ([page MCP de Gemini CLI](https://geminicli.com/docs/tools/mcp-server/)).
- Sur cette même page MCP, pour un serveur fourni par une extension, les valeurs locales de `settings.json` l'emportent sur les valeurs par défaut de l'extension. C'est la règle "le local prime sur les extensions" : elle concerne les extensions de Gemini CLI, pas Antigravity.
- La [page de migration d'Antigravity CLI](https://antigravity.google/docs/cli/gcli-migration) de Google indique : "Legacy Gemini config: Servers were declared inline within `~/.gemini/settings.json`" et que les serveurs d'Antigravity CLI "are defined inside a standalone `mcp_config.json` profile".

Non vérifié par VantagePeers : si l'IDE Antigravity lit un bloc `mcpServers` depuis `~/.gemini/settings.json` ou depuis un `.gemini/settings.json` de projet. Aucune page Google Antigravity trouvée ne l'affirme, et la page de migration dit le contraire pour la CLI. Ce guide n'utilise donc pas `settings.json`, et un fichier de projet n'est pas proposé pour donner à chaque workspace sa propre entrée. Garde une entrée par agent dans le fichier global, comme ci-dessus.

### Dossier de plugin au niveau du workspace

La [documentation des plugins](https://antigravity.google/docs/plugins) de Google indique qu'un dossier de plugin placé dans `.agents/plugins/` à la racine du workspace ne s'active que pour ce projet, et qu'un dossier placé dans `~/.gemini/config/plugins/` s'active pour tous les workspaces. L'installeur VantagePeers n'utilise pas de dossier de plugin : il installe les skills dans `.agents/skills/` et écrit l'entrée MCP dans le fichier global.

## Émettre un access token manuellement

Si ton client ne peut pas exécuter OAuth automatiquement, tu peux exécuter le flux PKCE toi-même et coller l'access token résultant dans un header `Bearer`. Bash :

```bash
BASE="https://vantage-peers-production.up.railway.app"
CLIENT_ID="YOUR_CLIENT_ID"
CLIENT_SECRET="YOUR_CLIENT_SECRET"
REDIRECT="http://localhost:3000/callback"

# 1. Verifier + challenge PKCE (S256)
VERIFIER=$(openssl rand -base64 64 | tr -d "=+/" | head -c 64)
CHALLENGE=$(printf "%s" "$VERIFIER" | openssl dgst -sha256 -binary | openssl base64 | tr -d "=" | tr "+/" "-_")

# 2. Affiche l'URL d'authorize — ouvre dans un navigateur, accepte, copie le `code` depuis l'URL de callback
echo "$BASE/oauth/authorize?response_type=code&client_id=$CLIENT_ID&redirect_uri=$REDIRECT&code_challenge=$CHALLENGE&code_challenge_method=S256&scope=mcp:full"

# 3. Après consentement, échange le code contre un access_token
read -p "Colle le code depuis l'URL de callback : " CODE
curl -s -X POST "$BASE/oauth/token" \
  -H "Content-Type: application/x-www-form-urlencoded" \
  -d "grant_type=authorization_code" \
  -d "code=$CODE" \
  -d "client_id=$CLIENT_ID" \
  -d "client_secret=$CLIENT_SECRET" \
  -d "redirect_uri=$REDIRECT" \
  -d "code_verifier=$VERIFIER" | jq .
```

La réponse contient `access_token` (courte durée) et `refresh_token`. Envoie `Authorization: Bearer <access_token>` sur chaque appel d'outil.
